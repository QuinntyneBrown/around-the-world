Theming

Three tiers of tokens, two themes, one file that holds every value.

Overview

tokens/tokens.css is the single source of truth. Components read semantic tokens; themes change semantic tokens; nobody else writes a value.

The three tiers

TierPrefixExampleWho uses it
Primitive--palette-*, --font-*--palette-red-600Semantic tokens only
Semantic--color-*, --text-*, --space-*, --radius-* …--color-action-playComponents and screens
Component--toy-face, --kid, --alert-bg--toy-face: var(--color-action-play)One component, in components.css

How themes apply

  • Light is :root.
  • Dark applies with data-theme="dark" on any element, or when the device prefers dark and the page has not set data-theme="light".
  • Each theme sets color-scheme.
  • prefers-contrast: more strengthens edges and secondary text; forced colours hand the focus ring and edges to the system.

The cast’s colours

Put data-kid="zuri" (or kenji, nia, milo, pip, classmate) on any element. It sets four component properties for everything inside: --kid, --kid-deep, --kid-tag-bg and --kid-tag-fg. Portraits, tags, the timer bar, ring dots, stickers and podium steps all read them.

ZuriKenjiNiaMiloPip

Adding a theme

  • Add a [data-theme="name"] block that overrides semantic tokens only.
  • Add its pairs’ results by running the contrast check; every pair must pass.
  • Do not change the cast’s colours or the picture colours in a theme.

tokens.json

tokens/tokens.json is the same tokens in the Design Tokens (DTCG) format, with dark values under $extensions, for tools that are not CSS. It is generated: change tokens.css and export again.

Usage

  • Never a hex value outside tokens.css. The checker fails on one.
  • Never name a token after a value or a single place it is used.
