Pattern

Choices and the code field

How a child sets things up: toggles and choices that take effect at once, and the one field in the game.

WCAG 2.2 AAStatus: stable
  • Overview
  • When to use what
  • Structure
  • States
  • Responsive behaviour
  • Accessibility
  • Content
  • Do and don’t
  • Sources

Overview

The game has no forms in the usual sense. A child chooses by pressing things that show their state, and types exactly once: four letters to join a room.

When to use what

To chooseUse
Any number of a few things, at least oneToggle chip, Table key
Exactly one of threeChoice or Segmented choice
One of the five kidsKid picker
A setting that is on or offSwitch
A room’s codeCode field
A nameNothing to type: Nickname rolls one

Structure

6 seconds per card

Choices change at once; the one big button is the way on

States

StateWhat shows
DefaultsA game can start with no changes: Times, tables 2 to 10, 12 desks, Normal
The last one onIt stays on, and a line says “Keep at least one kind of maths on.”
A group that does not applyIts keys are disabled and a line says why
Saving (the host, to a room)The button is busy: “Saving…”; the choices wait
RefusedAn alert above the button; the room keeps its old setup
A wrong codeRed boxes and an alert under them; the letters stay

Responsive behaviour

One column on a phone, two from 992px with the main choice first. The button is at the end of the last column and full width.

Accessibility

  • Every choice is a native button with aria-pressed, in a group named by its heading.
  • The hint under a choice is a polite live region, so the new value’s meaning is read.
  • The code field is a real input with a label, help and an error joined by aria-describedby.
  • Nothing is validated on a timer; the code is checked when Join is pressed.

Content

  • Headings ask the question: “Which maths?”, “How far round?”.
  • Hints give the consequence in numbers: “about 5 minutes”, “6 seconds per card”.
