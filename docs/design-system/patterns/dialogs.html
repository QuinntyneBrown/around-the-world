Pattern

Dialogs and overlays

When the game stops to ask, and when it stops because it must.

WCAG 2.2 AAStatus: stable

Overview

Three things cover a screen: a dialog (a decision), a status overlay (waiting), and a sticker or message (passing by).

When to use what

NeedUse
The child chose to stop: Pause, Leave, SettingsDialog
The game cannot go on: ReconnectingStatus overlay
Something to notice that needs no answerToast, Map message or a Sticker
Anything with more than two sentencesA screen, not a dialog

Structure

Paused

The clock is stopped. Your desk at Italy is waiting.

The safe choice is first, biggest and focused

States

StateRule
OpenThe screen behind is inert and dimmed; a solo game’s clock is stopped
BusyThe pressed button is busy; the other is disabled
ClosedFocus returns to the button that opened it

Responsive behaviour

A dialog is a sheet from the bottom under 576px and a centred card above. A status overlay is always a centred card.

Accessibility

  • The modal dialog pattern: focus is held inside, Escape takes the safe choice, the title names it.
  • Never open a dialog on a dialog.
  • A status overlay is an alert, read at once.

Content

  • Titles: “Paused”, “Leave the game?”, “Settings”.
  • Buttons say what they do: “Keep playing”, “Go home”, “Stay and play”, “Leave”, “Done”.
