Alert and banner

A message that stays in the page: something could not be done, or something to know before going on.

WCAG 2.2 AAStatus: stableBlock .alert

Overview

Use an alert inside a screen, next to what it is about, and a banner across the top for something about the whole game (offline, a wobbly connection). Use a toast for a passing event.

Anatomy

  1. IconMatches the tone
  2. TitleWhat happened
  3. TextWhat it means
  4. ActionsText buttons

Responsive behaviour

It fills its column. A banner spans the screen.

Theming

It reads semantic tokens only, so it follows the theme with no rule of its own. To restyle it, override its component custom properties or the semantic tokens listed under Tokens; never write a colour into the component.

Accessibility

Role and pattern

role="alert" for a failure that just happened; role="status" for news that needs no action.

Content

  • Title: what happened, in a child’s words. Text: what it means and what to do.
  • Never the backend’s message, a code or a stack trace.
  • Say what still works: “You can still play solo.”
